Aufgabe #7 vom persönlichen Miro-Board: Dateien, Projekte & die Kommando­zeile
 
In der Session Git & GitHub: Versionskontrolle & Kollaboration (VC B05-08) hast du gelernt, wie du Änderungen als Snapshots speicherst, mit Branches experimentierst ohne das Original zu riskieren – und wie Code über GitHub im Team landet. Jetzt setzt du den kompletten Workflow selbst auf: vom ersten git init bis zum Pull Request auf GitHub.
 
## Aufgabe: 7-Tage-Entwicklertagebuch

Erstelle ein GitHub-Repository und führe es sieben Tage lang als Lerntagebuch – ein Commit pro Tag, mindestens ein Branch und ein Pull Request.

## Dein Output: Ein Repository auf GitHub mit

- einer README.md
- 7+ Commits
- 1+ Branches und Pull Request


Repository anlegen: mein-lerntagebuch
Auf GitHub — öffentlich oder privat, deine Wahl
Jeden Tag: eine Markdown-Datei
tag1.md bis tag7.md — Was gelernt? Welches Problem? Wie gelöst?
Branch anlegen & PR mergen
Mindestens einen Feature-Branch + Pull Request auf sich selbst

## ACHTUNG:

Ich werde 1-2 Pull Requests erstellen und danach nur noch per ```git push``` direkt in den main Branch pushen.

Grund: Ich arbeite alleine am Repository und Pull Requests sind ein Overhead!
